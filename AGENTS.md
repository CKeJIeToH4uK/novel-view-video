# Правила разработки

## Перед изменением

Прочитайте этот файл, README и относящийся раздел ARCHITECTURE.md.
Для Python-компонента прочитайте также diffusion/code/AGENTS.md,
его архитектуру и затрагиваемые код и тесты. Не перечитывайте неизменные
документы целиком после каждого шага: восстанавливайте конкретное решение.
Проверьте ветку, remote и незакоммиченные изменения; чужие правки сохраняйте.

## Простота и научные границы

- Внутренний пакет остаётся novel_view, пользовательский запуск — ./distil3d.
- Данные — маленький dataclass, вычисление — функция, живущее состояние —
  конкретный класс, научный порядок — явная run_vN().
- Обобщение появляется после второго совместимого реального использования.
  Не вводите заранее Manager, Service, Factory, BaseWorkflow, BaseTrainer,
  общий InputAdapter, registry или склад utils.
- Workflow вызывает предметные области; обратные импорты не добавляются.
  Production не импортирует tests или research.
- Не меняйте научный порядок старой версии молча. Новый опыт получает
  отдельную версию; исправление ошибки описывается как исправление.
- Обычный запуск доверяет настроенной оператором машине. Не добавляйте
  filesystem preflight, повторные type/shape checks, paths.py, staging,
  atomic/no-overwrite, worker-output validator или checkpoint compatibility.
- Строгие внешние схемы и предметные научные инварианты сохраняются.
  Ошибки модели, данных и процесса не скрываются общим перехватом.
- Полная диагностика выполняется только явным doctor или accept.

## Проверки и данные

Проверяйте изменённое поведение и ближайшие стыки коротким набором тестов.
Не тестируйте каждый текст ошибки и порядок приватных вызовов.
Docker запускается только на явно разрешённом Linux; на локальном Mac
владельца его не запускать. GPU, платные ресурсы, передача данных, изменения
видимости и переписывание истории требуют отдельного разрешения.

Модели, данные, окружения, checkpoints, полные результаты, ключи и личные
profiles/jobs/selections не добавляются в Git. При публикации остаются
лицензии и атрибуция. Не заявляйте аппаратные проверки, которых не было.

## Завершение

Обновите относящиеся README и архитектуру при изменении структуры.
Новая постоянная пользовательская папка получает README; малому Python-
пакету достаточно паспорта в __init__.py. Коммит должен содержать цельное
проверенное изменение. Не отправляйте изменения и не меняйте настройки
репозитория без поручения пользователя.
