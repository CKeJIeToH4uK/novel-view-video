# Правила Python-компонента

Прочитайте корневой AGENTS.md и относящийся раздел этой архитектуры.
Затем читайте конкретные входы, выходы, реализацию и ближайшие тесты.
Внутренних plans/ или журналов миграции в публичной копии нет.

Пакет остаётся src/novel_view; пользовательский запуск — корневой ./distil3d.
Модельные зависимости импортируются внутри worker-границы. Production
не импортирует tests или research. Форматы научных результатов, порядок
окон и RNG, checkpoint/resume и единицы камер/глубины не меняются молча.

Новый метод сначала является конкретным соседним модулем, а не общим
BaseTrainer/Manager. Данные — dataclass, вычисление — функция,
дорогое живущее состояние — конкретный класс. Повторные проверки путей,
внутренних типов, атомарная публикация и compatibility gates не добавляются.
Внешние схемы и необходимые научные инварианты сохраняются.

Проверяйте поведение короткими тестами; не создавайте production-код ради
тестовой обвязки. Docker — только разрешённый Linux, никогда локальный Mac
владельца. Реальная GPU-проверка требует отдельного поручения.
Обновляйте README, ARCHITECTURE.md и паспорта изменённых областей.
