# Novel View Pipeline

Python-компонент `novel_view`: чтение EUVS/nuPlan, Gaussian export и Waymo,
геометрия, Gen3C generation, Waymo/DDW preparation, R4c LoRA и оценка.

Команды запускаются из корня всего репозитория через `./distil3d`.
Отдельного пользовательского CLI из этой папки нет.

## Границы

EUVS source views/generation/evaluation/comparison и пять Gaussian-порядков
имеют конкретные workflow. Waymo/DDW preparation, R4c LoRA v1, выбор
checkpoint и matched evaluation используют те же jobs и жизненный цикл
попыток. Исторические сценарии доступны через `jobs/legacy/`.

V2 с лоссом глубины — отдельный эксперимент, не молчаливая замена v1.
DA3 находится только в `research/da3_nested/`, не входит в wheel,
поддерживаемые jobs или образы. Временная команда `novel-view` показывает
лишь справку/версию до завершения Stage 11.

Исходная версия прошла CPU-проверки, упаковку и жизненный цикл контейнеров;
настоящая модельная приёмка опубликованной версии ещё не выполнена.
CP4 и v2 GPU/A/B повторно не проверены. Однокарточный `accept` пока не реализован.
Синтетические tracked selections
показывают форму входа, а не заменяют реальные данные.

## Состав

- `src/novel_view/` — production; не импортирует tests или research.
- `tests/` — отдельные unit/contract/integration-доказательства.
- `research/` — экспериментальный код вне установленного пакета.
- Актуальные lock-файлы и Dockerfile — в корневом `containers/diffusion/`.
- `pyproject.toml` — сборка wheel; editable-установка не является запуском проекта.

Новые модули добавляются к существующему предметному владельцу.
При изменении границ обновляются архитектура и паспорт соответствующей области,
а не создаётся параллельная общая архитектура.
